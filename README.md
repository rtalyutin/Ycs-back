# YCS results backend

Отдельный backend ЯрКиберСезона: OpenDota → публичный JSON в Timeweb S3.
Сайт и Mini App остаются в `rtalyutin/yarcyberseason` и читают тот же объект S3.
Backend не собирает и не обслуживает React, не зависит от посещений сайта
и не коммитит результаты в GitHub.

Код импортёра и общие данные перенесены без изменения из
[`yarcyberseason@088afb3`](https://github.com/rtalyutin/yarcyberseason/commit/088afb38046175d102d3f6f98f3c582701a158e5).

## Timeweb App Platform

| Поле | Значение |
| --- | --- |
| Репозиторий | `rtalyutin/Ycs-back` |
| Ветка | `main` |
| Тип приложения | Backend |
| Фреймворк | Dockerfile |
| Путь к директории проекта | Пустой: Dockerfile находится в корне |
| Сборка и запуск | Инструкции из Dockerfile |
| Порт | `8080`, указан через EXPOSE |
| Проверка состояния | `/healthz` |
| Экземпляры с включённым импортом | Один |
| Приватная сеть | Не требуется |
| Пользовательский домен | Не требуется |

Контейнер использует Node.js 22; отдельная настройка версии Node в панели не нужна.
Тариф сервера выбирается владельцем перед запуском платного приложения.

### Переменные окружения

- `AWS_ACCESS_KEY_ID` — ключ пользователя S3 с правами чтения и записи объекта результатов.
- `AWS_SECRET_ACCESS_KEY` — секретный ключ этого пользователя.
- `YCS_DOTA_RESULTS_IMPORT_ENABLED=true` — включённый импорт (значение по умолчанию).
  Установите `false`, чтобы отключить импорт на дополнительном экземпляре.

Ключи задаются только в окружении backend, без префикса VITE_.
Не сохраняйте их в репозитории, Dockerfile или клиентском приложении.

## Запуск и проверка локально

Нужен Node.js 22.12+.

```sh
npm ci --prefix backend
npm test
npm start
```

`GET /healthz` возвращает `200 {"status":"ok"}`; HEAD также поддерживается.
Это подтверждает работу HTTP-процесса, но не наличие доступа к S3
или успешный импорт. Остальные URL возвращают 404, другие методы health — 405.
Публичного HTTP-триггера импорта нет.

## Расписание и публикация

Лига OpenDota: `20164`. Проверка выполняется каждые пять минут только в окнах МСК:

- 9 октября 2026, 20:30 → 10 октября, 01:00.
- 10 октября 2026, 20:00 → 11 октября, 01:00.

До начала окна API и S3 не вызываются. Следующая проверка планируется после
завершения предыдущей; ошибка записывается в лог и проверяется снова следующим
циклом. SIGTERM/SIGINT останавливают цикл и прерывают сетевые запросы.

S3 endpoint: `https://s3.twcstorage.ru`, регион `ru-1`.
Бакет: `e9dc5ea4-6dc9267d-85ca-4ae9-a41f-2895e9542a04`.
Объект: `results/dota2-autumn-2026.json`.

Публикуются только однозначные завершённые серии. Победитель карты определяется
radiant_win, не числом убийств. Повтор не создаёт новую revision. Конфликт,
неизвестная команда и неполная серия не получают выдуманный результат.
После записи выполняется чтение результата из S3. Версии объекта нужно включить
в бакете; для сайта и Mini App разрешить публичное чтение и CORS GET/HEAD с
`https://xn--90aiaibl0ahlel5n.xn--p1ai` и `https://ycs.bar`.

**Один активный writer, без перекрытия deployments.** Сериализация защищает
один процесс, распределённой блокировки S3 нет. При замене backend сначала
остановите прежний writer. Старый JSON остаётся в S3 и перечитывается после
перезапуска.

Для следующих туров обновляйте опубликованные fixtures в JSON турнира
согласованно с frontend-репозиторием и добавляйте подтверждённые окна в backend.

Старую лигу можно проверить отдельной командой
`node backend/dota-results-import.mjs --probe-old-league`: один матч лиги 19021,
без обращения к S3 и публикации. Этот probe не выполняется при обычном запуске.

## Граница проверки

Локальные тесты используют двойники OpenDota/S3. Успешный локальный запуск
не подтверждает Timeweb, реальные ключи/CORS и настоящую запись S3.
После настройки окружения нужно отдельно подтвердить цепочку
OpenDota → S3 readback → сайт и Mini App.
